# Change a MISRA Zig rule

The markdown handbook is the one source of wording. Everything else derives
from it or is tested against it. Work from the repo root.

## Files and what each owns

| File | Owns |
|---|---|
| `AGENTS.md` | The rule set in seven groups, the cited MISRA ids per group, the compiler-rejected list, where a rule departs from the MISRA text |
| `docs/misra-zig-handbook.md` | Per rule: `### Rule N.M` or `### Dir N.M`, the obligation, `#### Do`, `#### Don't` |
| `docs/misra-c-2025.md` | The status of every MISRA C:2025 guideline in Zig; ids are C:2025 numbers |
| `docs/examples/compliant.zig` | Every do function, tested in Debug and ReleaseSafe |
| `scripts/handbook.ts` | `GROUP_DEFS`: group titles, blurbs, and which ids sit in each |
| `scripts/handbook.test.ts` | Rule counts and the marks of chosen rules, asserted by value |
| `scripts/lint.test.ts` | `UNDECIDED`: compiling don'ts misra-lint cannot flag, each with its reason |
| `tools/misra_lint.zig` | Checks that decide a don't from the syntax tree |
| `tools/std_lists.zig` | Generated by `bun scripts/gen_std_lists.ts` from the installed std; never edited by hand |

The site, `/rules.json`, the pin map, and the review checklist
(`scripts/review.ts`) are generated from these. They need no edit.

## Before writing a claim

Every sentence about Zig behavior is checked against Zig 0.17.0 first. Put a
one-file probe in `.scratch/`, then compile it (`zig test --test-no-exec`) or
run it (`zig run -ODebug`) and read the result. "Panics in a safe build" is
written only after a run shows the panic.

## Handbook format

- A don't sample is led by a paragraph that starts `**Rejected.**` (Zig 0.17
  refuses it) or `**Compiles.**` (accepted and still wrong). A don't with no
  sample is a lead paragraph alone, pointing at another rule.
- A rejected sample is an `export fn` (an uncalled function is not analyzed).
  `handbook.test.ts` fails otherwise.
- A do sample must compile inside `wrapSource` (`scripts/check.ts`). The
  wrapper adds `std`, `Header`, `Color`, `Opcode`, `sumWide`, `Node`,
  `readSome`, and `captureErrno` when the sample names them without declaring
  them. Any other helper is declared in the sample.
- Copy every do function into `compliant.zig`, with a test of the success path
  and of each error.

## Steps

1. Edit the handbook section. The wording is the Zig obligation, not MISRA C
   text, and the source project stays unnamed.
2. Update `AGENTS.md`: the group section's text, its cited MISRA ids, and the
   compiler-rejected list. A new rule id goes into `GROUP_DEFS`, and a group
   rename goes into both. Change the guideline's row in `docs/misra-c-2025.md`
   and the counts above its tables.
3. Update `compliant.zig` and its tests.
4. Update `handbook.test.ts` where it asserts the group count, the rule count,
   or the marks of a rule you changed. A new group also changes the group
   count in `AGENTS.md` ("Seven groups").
5. A new `**Compiles**` don't must be flagged under its own rule. Add a check
   with the `misra-lint-check` skill, or add the sample to `UNDECIDED` with what
   a syntax tree cannot see.
6. Run the gate:

```bash
zig fmt --check .
zig test -lc -ODebug docs/examples/compliant.zig
zig test -lc -OReleaseSafe docs/examples/compliant.zig
zig test -ODebug tools/misra_lint.zig
zig test -OReleaseSafe tools/misra_lint.zig
bun test scripts/
bun scripts/check_samples.ts
```

`check_samples.ts` compiles every sample and compares the result with its mark.

7. Measure the counts and update `README.md` and `docs/misra-lint.md`: rules
   from `bun test`, checks from `misra-lint --checks`, coverage from
   `bun test scripts/lint.test.ts`. Never write a count from memory.
8. Open `bun scripts/server.ts`, load the rule's sheet, and check the marks,
   the evidence line on each don't, and the characteristics.
9. Append an entry to `docs/ledger.md`.
