# Add a misra-lint check

`tools/misra_lint.zig` parses one file with `std.zig.Ast` and has no types and
no data flow. A check belongs there only when the syntax tree alone decides it.
When it does not, the don't stays in `UNDECIDED` in `scripts/lint.test.ts` with
the reason.

## How the checker is built

- One flat pass over the node array (`lintNode`), then per function (`lintFn`),
  then file-wide passes (`lintOpens`, `lintRecursion`). There is no recursive
  tree walk: the tool follows Rule 17.2 itself.
- `enclosingFn(token)` finds the innermost function by token range.
- Statement-order checks (`lintStatements`) see one block's statement list.
- Token scans (`tokensHoldIdent`, `isErrnoAt`) cover what the tree does not
  model, such as `std.c._errno().*`.
- Reusable questions: `isChain(node, &.{"std", "heap", ...})` for a field
  chain, `isParam(f, name)`, `comparedIn(first, last, name)` for "a comparison
  next to this name", `uncheckedParam(node, at)` for "a parameter never
  compared before `at`", `arithType` for the width of a typed `+ - * <<`.
  Reuse them before writing a new scan.
- Std facts come from `tools/std_lists.zig` (`std_lists.deprecated`,
  `std_lists.posix_assumes_errno`), generated by `bun scripts/gen_std_lists.ts`.
  A new list belongs in that generator, not hand-written in the checker.
- `inMainOrTest(token)` is the entry-point test (main, tests, `build`).
- `info(check)` holds the severity, the handbook rule ids, and the one-line
  summary. The rule ids must exist in the handbook; `bun test scripts/` checks.

## Steps

1. Write the failing test first, in the `test` blocks at the end of
   `tools/misra_lint.zig`: the don't sample must produce the check, and a near
   miss that is compliant must not. Run `zig test -ODebug tools/misra_lint.zig`
   and see it fail for the right reason.
2. Add the `Check` tag, its `info` entry, and the code. Use `violation` when the
   pattern is the breach, `review` when a reader decides.
3. Keep the checker inside its own standard: no recursion, no `anyerror`, no
   `catch {}`, `std.math.cast` instead of `@intCast` without a check, and the
   arena passed in. `misra-lint tools/misra_lint.zig` must stay clean. A
   justified exception carries `// misra-lint: allow <check> <reason>`.
4. Remove the sample's key from `UNDECIDED` in `scripts/lint.test.ts`.
5. Run misra-lint on a real Zig project outside this repo (any repo under
   `~/Desktop/Projects` with `.zig` files) and read every new finding. A check
   that fires on correct code there gets narrowed or becomes `review`.
6. Run the gate: `zig fmt --check .`, `zig test -ODebug` and `-OReleaseSafe` on
   `tools/misra_lint.zig`, `bun test scripts/`. The do samples and
   `docs/examples/compliant.zig` must still lint clean.
7. Update the check count and coverage numbers in `README.md` and
   `docs/misra-lint.md` by measuring them (`misra-lint --checks`), never from
   memory. Append an entry to `docs/ledger.md`.
